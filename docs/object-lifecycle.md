# Жизненный цикл объекта Z8

Исследование выполнено по исходникам `org.zenframework.z8`:

- `server/runtime/CLASS.java`, `IClass.java` и `OBJECT.java` определяют ссылку,
  объект и стадии инициализации;
- `compiler/parser/type/members/TypeBody.java`, `Member.java` и `MemberInit.java`
  формируют порядок инициализации полей;
- `compiler/parser/variable/VariableType.java`, `expressions/OperatorNew.java` и
  `expressions/Postfix.java` определяют создание ссылки и стадии её раскрытия.

`new` создаёт ссылку `CLASS`, а не готовый `OBJECT`. При `CLASS.get(stage)`
сначала до запрошенной стадии доводится контейнер, затем при необходимости
создаётся объект. Стадия `Constructor1` выполняет инициализацию ссылочных полей
и `initMembers`; стадия `Constructor2` — остальные инициализаторы и пользовательский
конструктор. Значение стадии устанавливается **до** вызова соответствующего кода:
после исключения повторное обращение не запускает уже начатую стадию заново.

Для производного класса инициализаторы ссылок собираются по всей иерархии и
упорядочиваются с учётом имён и зависимостей. На стадии `Constructor2` сначала
вызывается метод предка, затем инициализируются поля текущего класса. Пользовательский
конструктор вызывается виртуально; вызов `super.constructor()` явный. Создание
ссылки, проверка на `null` и `instanceof` не раскрывают объект.

В z8-d текущие классы используют отдельные стадии создания полей, ссылочных
инициализаторов и остальных значений; вложенные массивы `auto`, атрибуты и иные
стадии, отсутствующие в поддерживаемом подмножестве языка, сюда пока не входят.
Поведение проверяется исполняемыми примерами и сравнением с оригинальным
компилятором и доступным собранным Java runtime.
