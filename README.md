# z8-d

Начало переноса платформы ZENFRAMEWORK Z8 на D. Реализованы лексический анализ
языка Z8 (`.bl`) и экспериментальная трансляция ограниченного подмножества языка
в D. Это **не полная реализация Z8**: стандартная библиотека, полноценный runtime,
сервер и веб-клиент пока отсутствуют.

## Устройство исходного кода

Границы модулей учитывают устройство исходного компилятора Z8: его грамматика,
выражения и операторы организованы в `compiler/parser`, работа с единицами
компиляции — в `compiler/workspace`, а генерация кода — в `compiler/core`.
В z8-d этим этапам соответствуют:

- [lexer.d](source/z8/lexer.d) — лексический анализ;
- [compiler_model.d](source/z8/compiler_model.d) — модель программы, типы и ошибки;
- [parser.d](source/z8/parser.d) — построение модели по исходному коду;
- [semantic.d](source/z8/semantic.d) — проверка имён, типов и семантики;
- [emitter.d](source/z8/emitter.d) — генерация D-кода;
- [d_writer.d](source/z8/d_writer.d) — форматирование сгенерированного D-кода;
- [compiler.d](source/z8/compiler.d) — публичный интерфейс и компиляция проекта.

Содержимое runtime разделено на фрагменты базовых операций, массивов, отображений,
строк и десятичных чисел. Это соответствует разделению оригинала между
`server/runtime` и `server/types`: например, коллекции представлены там классами
`RCollection` и `RLinkedHashMap`. [runtime_source.d](runtime/source/z8/runtime_source.d)
собирает фрагменты, а [runtime.d](runtime/source/z8/runtime.d) входит в отдельную
статическую библиотеку. Сгенерированные файлы подключают её через `import z8.runtime`.
Шаблоны D дополнительно проверяются при их
инстанцировании в интеграционных тестах сгенерированных программ.

## Сборка и запуск

Требуются DMD и DUB. Внешние пакеты D не используются.

```sh
dub build
dub test
dub run -- lex path/to/file.bl
dub run -- compile examples/math.bl
dub run -- project examples/project generated
dub run -- build examples/project demo.Main.run example-app
python tests/integration.py
python tests/decimal_oracle.py
python tests/string_oracle.py
python tests/lexer_oracle.py path/to/original-z8 --corpus
python tests/z8_compiler_oracle.py path/to/original-z8
```

Интеграционные проверки требуют Python 3 и DMD в `PATH`; двум проверкам с суффиксом
`oracle` также нужен JDK с `java` и `javac`. Они компилируют сгенерированный D-код
и сравнивают результаты с Java `BigDecimal` и строками UTF-16.
Две последние проверки дополнительно используют исходники оригинального Z8;
для проверки компилятора нужны также его кэшированные Eclipse-зависимости. Если
задать переменную `Z8_ORACLE_RUN=1`, пример проекта дополнительно выполняется и
сравнивается с D-версией, используя имеющиеся собранные классы и JAR оригинального
runtime. Этот JAR может отличаться по версии от текущих исходников.

`z8d lex` выводит по одному JSON-объекту на токен. `kind` — категория,
`text` — исходное написание, `offset` и `length` измеряются в кодовых единицах
UTF-16, `line` и `column` отсчитываются с нуля. Пробелы и комментарии пропускаются.
Ошибка лексического анализа выводится в stderr с позицией, код выхода — 1;
неверные аргументы дают код 2. Файл должен быть в UTF-8.

Поддерживаются ключевые и зарезервированные слова исходного компилятора,
операторы, вложенные блочные и однострочные комментарии, строки с escape-последовательностями,
числа, даты, интервалы, GUID и бинарные литералы. Семантические значения литералов
пока не вычисляются: наружу возвращается исходный текст. Unicode-идентификаторы
проверяются по категориям букв и чисел D, поэтому возможны отличия от Java
`Character.isJavaIdentifierPart`. Совместимость не подтверждена для всех краевых
случаев оригинального лексера.

### Трансляция в D

`z8d compile file.bl` разбирает исходный текст, проверяет типы и выводит D-код
в stdout. Результат представляет собой библиотечный код, а не готовую исполняемую
программу. Ошибки выводятся в stderr с позицией; при ошибке код не выводится.

Поддерживается один класс или перечисление на файл. Для перечислений реализованы
именованные значения, сравнение, `null`, поля с явным инициализатором, параметры,
возвращаемые значения и `?:`. Атрибут `[native "..."]` в объявлении перечисления
распознаётся, но связь с внешним Java-типом не создаётся. Для одномерных массивов
перечислений поддерживаются те же основные операции, что для массивов объектов.
Статические поля перечислений и переменные перечислений без явного инициализатора
пока не поддерживаются; для последнего случая оригинальный компилятор генерирует
некомпилируемую Java.

Классы поддерживаются с реализованными статическими
и экземплярными методами. Методы можно перегружать, в том числе добавляя
экземплярные перегрузки в наследнике; смешивание статических и экземплярных
перегрузок одного имени и перегрузки унаследованных статических методов пока не поддерживаются.
Внутри класса доступны поля базовых
и объектных типов, `this`, `new ИмяКласса` и локальные переменные объектного типа.
Статические поля поддерживаются для базовых типов и их одномерных массивов;
инициализатор статического поля пока должен быть константным выражением.
Оригинальный компилятор запрещает статические поля пользовательских классов.
Видимые классы можно использовать в параметрах и возвращаемых значениях, а также
обращаться к их публичным полям и методам. Объектные поля создаются лениво,
поэтому допускаются рекурсивные типы и циклические ссылки между типами.
Поддерживается одиночное наследование через `extends`, публичные и защищённые
унаследованные члены, `super` и переопределение виртуальных методов с совпадающими
сигнатурами. Полное поведение объектов и сложные сценарии наследования ещё не перенесены.
Поддерживаются явные приведения между базовым и производным классами с проверкой
типа во время выполнения; другие объектные приведения пока не реализованы.
Для таких классов также поддерживается проверка типа `instanceof`.
При первом обращении инициализация проходит стадии ссылочных полей и остальных
значений; перед инициализацией вложенного объекта его контейнер доводится до нужной
стадии. Базовый `void constructor()` без параметров вызывается после инициализации
полей предков и текущего класса; переопределённый конструктор может явно вызвать
`super.constructor()`. Автоматические массивы `auto`, атрибуты и выражение
`container` пока не поддерживаются.
Типы: `int` (64-битный знаковый), `decimal`, `bool`,
`string`, `guid`, `binary`, `datespan`, `date`, `geometry`, `file`, `exception`, `primary`, одномерные массивы этих типов и `decimal[][]`
и пользовательских классов,
а также `void` (для возвращаемого значения).
`primary` принимает значения `int`, `bool`, `decimal`, `string`, `guid`, `binary`, `datespan`, `date`, `geometry`, `file` и `null`,
поддерживает передачу в методы, возврат и методы `toString()` и `hashCode()`.
Поля и локальные переменные `primary` требуют явного инициализатора: исходный
компилятор при его отсутствии создаёт некомпилируемую Java с абстрактным `primary`.
Поддерживаются одномерные массивы `primary`, отображения `primary[string]`,
проверка `instanceof` и приведение к перечисленным типам.
Для `guid` поддерживаются литералы, `Null`, `parse`, варианты `create`, сравнения,
`major`, `minor`, `components`, `toString`, `hashCode` и передача через `primary`.
`parse` принимает каноническую запись UUID, запись из 32 цифр и укороченные
пятичастные записи по правилам Java 8.
Для `guid.create(string)` используются байты UTF-8.
Для `binary` поддерживаются литералы, длина, поле `name`, операции с именем,
`toString`, `hashCode`, передача через `primary`, создание и распаковка ZIP,
преобразование из строки UTF-8 и файла. Файл при преобразовании в `binary`
открывается как поток: последующее чтение или копирование потребляет и закрывает
его, тогда как двоичные данные в памяти после чтения остаются доступны с нулевой длиной.
`binary.zip` возвращает поток временного файла; само построение и разбор ZIP пока
используют буфер в памяти.
Хеш двоичного значения определяется его идентичностью
в текущем процессе, как у объекта в оригинале; численное значение зависит от среды.
Для `datespan` реализованы литералы, `parse`, арифметика и сравнение интервалов,
получение и изменение компонентов, усечение, преобразование в строку и `hashCode`.
Для `date` поддерживаются календарные литералы, текущее время, основные компоненты,
сравнения, прибавление и вычитание интервалов, добавление календарных единиц,
присваивание миллисекунд и преобразование `int` в новую дату, общие изменяемые
`Min`/`Max`, изменение компонентов,
чтение и установку часового смещения и усечение. `parse` и `parseIsoString` поддерживают
проверенное подмножество ISO-форматов; `parse` также принимает время в миллисекундах.
Используется московский часовой пояс с переходами с 1900 года по IANA tzdata 2025b
и настройками Java 8 для более ранних дат. Для периода 1900–2020 переходы, летнее
время и отдельные случаи прибавления дней сверены с Java; ранний календарь,
отличия версий базы часовых поясов и отдельные правила округления могут давать другой результат.
Чтение и установка календарных полей учитывают переход с юлианского календаря
на григорианский в октябре 1582 года, включая `date.Min` и даты до н. э. Для ранних
дат также проверены отдельные случаи арифметики, усечения и недельных шаблонов;
полная совместимость раннего календаря ещё не подтверждена.
`weekOfYear` пока использует понедельник
как первый день недели, как в русской локали Java. Форматирование по шаблону
и разбор по шаблону поддерживают числовые поля даты и времени, смещение и кавычки,
в том числе скользящее столетие для двухзначного года. Названия месяцев и дней
недели реализованы для русской локали; поддерживается разбор по номеру недели и
дню недели. Именованные часовые пояса и эры поддерживаются частично. Некоторые
сочетания полей и другие шаблоны пока не реализованы.
Литерал только с временем, как и в оригинальном компиляторе, сохраняет момент
компиляции и игнорирует указанное время. `hashCode`, включая вызов через `primary`,
следует проверенным настройкам календаря русской локали и хешу московского пояса
OpenJDK; результат может отличаться при других локалях или версиях базы часовых поясов.
Для `geometry` поддерживаются пустая геометрия, точки, линии, составные линии,
кольца, полигоны и коллекции: создание, координаты, границы и `extent`, центр, длина,
точка на линии и перпендикуляр к ней,
идентификатор системы координат, WKB-представление в виде hex и его отложенный
разбор, чтение и запись GeoJSON, `hashCode` и передача через `primary`. Разбор
GeoJSON поддерживает также некоторые расширения исходного JSON-парсера; ряд
других методов геометрии ещё не реализован.
Составная геометрия сохраняет ссылку на переданный массив компонентов; границы,
длина и бинарное представление кэшируются при первом вычислении, как в оригинале.
`extent` возвращает вложенные массивы `decimal`; в оригинальном Java runtime
внутренние элементы представлены Java-массивами и при доступе из BL могут
вызвать ошибку приведения типов.
`fromArray` объединяет коллекции и пропускает пустые геометрии, используя
`DefaultSRS`: в BL оригинала объявлен один аргумент, тогда как соответствующий
метод Java дополнительно требует SRS.
Для `file` поддерживаются метаданные и операции с именем и путём, включая
присваивание строкового пути с сохранением ссылочной семантики и преобразование
строки в `file` при передаче в методы, проверка наличия,
чтение и запись UTF-8, запись `binary`, обход каталогов, удаление файлов или каталогов,
создание и распаковка ZIP-архивов,
а также `parse` и `toJson` для массивов метаданных. Разбор метаданных поддерживает
одинарные кавычки, ключи без кавычек и завершающие разделители, а также
проверенное подмножество форматов даты.
`createTempFile` выбирает имя по времени в подкаталоге `files/temp` рабочего
каталога, не создаёт файл сразу и удаляет его при штатном завершении процесса.
Как и в оригинале, одинаковые префикс и расширение в пределах секунды дают одно имя.
Реализованы массивы `file`; сравнение путей и сравнение элементов коллекции следуют
разным правилам оригинала. Относительные пути разрешаются от рабочего каталога;
пути с префиксом `storage` направляются в каталог хранилища, как в Z8. По умолчанию
это текущий каталог и его подкаталог `storage`; их можно настроить через
`Z8_WORKING_PATH`, `Z8_STORAGE_PATH` или вызов `z8_file_set_roots` при запуске.
Для чтения, записи и имён в ZIP поддерживаются кодировки
перечисления `encoding`: UTF-8, UTF-16, ASCII, CP866, KOI8-R и Windows-1250/1251/
1252/1253/1254/1257. Строковое
JSON-представление `file` может отличаться от оригинала порядком полей и форматированием.
В телах поддерживаются блоки,
локальные переменные, присваивания и составные присваивания, `return`, `if`/`else`,
`while`, `do`/`while`, обычный `for`, `break`, `continue`, вызовы методов того же
класса, целочисленные, логические и строковые литералы, тернарный оператор и часть
других операторов. Обычный `for` требует условия и выражения шага, как в грамматике
Z8; также поддерживается `for (тип элемент : массив)` для одномерных массивов.
Поддерживаются `throw` с `exception` или `string`, `try` с одним
`catch (exception ...)` и/или `finally`, а также `exception.getMessage()`,
`getStackTrace()` и преобразование исключения в строку. Формат стека определяется
runtime D и отличается от Java.
`null` поддерживается для переменных, аргументов и возвращаемых значений объектных
типов, исключений, строк, массивов и `string[string]`, включая сравнение с `null`. Для них также
поддерживается оператор `?:` с ленивым вычислением правой части.
Обращение к пустой ссылке вызывает исключение. `int`, `bool` и `decimal`
поддерживают `null` в переменных, полях, параметрах, возвращаемых значениях и
элементах массивов. Прямой инициализатор `null` у объектного поля принимается;
как и в оригинале,
первое обращение к такому объекту вызывает ошибку инициализации. Стадия не
откатывается при исключении, как и в исходном `CLASS.get`.
Переходы `return`, `break` и `continue` внутри `finally` пока не поддержаны.
Объявления без инициализатора получают значения `0`, `false`, пустую строку или
пустой массив; `exception` создаётся с пустым сообщением.
Проверяются имена, типы аргументов и выражений, области видимости и наличие
возвращаемого значения на всех путях. Затенение переменных запрещено.

Имя класса `Math` в D становится `Z8_Math`, а метод `add` — `m_add`; пример входа
находится в [examples/math.bl](examples/math.bl). `&&` и `||` сохраняют короткое
замыкание; деление и остаток учитывают крайний случай `long.min / -1`. Строки в D
представлены `wstring` (UTF-16), включая сравнение по кодовым единицам Java.
Поддерживаются конкатенация, сравнения, `length`, `isEmpty`, `compare`, `compareNoCase`, `startsWith`,
`endsWith`, `indexOf`, `lastIndexOf`, `substring`, `charAt`, `trim`, `trimLeft`,
`trimRight`, `left`, `right`, `insert`, `replace`, `padLeft`, `padRight`, методы смены
регистра, `replicate`, `concat` и `fromBinary` с кодировками `encoding`. Смена регистра использует
Unicode D и может отличаться от Java при специфичной локали или для отдельных символов;
обработка некорректных последовательностей UTF проверена на отдельных примерах.
При создании строки ключ `$имя$` заменяется ресурсом, заданным приложением через
`z8_string_set_resource`; если ресурс отсутствует, используется само имя ключа.
Функция `z8_string_load_nls(path)` загружает ресурсы из XML-файла `.nls` в UTF-8 или UTF-16;
она также настраивает локализованные значения `bool`, если они присутствуют в файле.
Поддерживается проверенное подмножество XML-формата Java Properties. Загрузку можно
выполнить при запуске приложения или указать пути к файлам в `Z8_NLS_FILES`, разделив
их системным разделителем путей (`;` в Windows, `:` в Unix). Автоматический поиск
`.nls` и проверка наличия ресурсов при компиляции пока не реализованы.
Методы `matches`,
`replaceFirst`, `replaceAll` и `split` используют общее подмножество синтаксиса
регулярных выражений Java и D; отдельные конструкции и некоторые случаи с UTF-16
могут отличаться. Классы `\d`, `\w` и `\s` по умолчанию ограничены ASCII;
флаг `(?U)` включает Unicode-классы в пределах своей области действия.
`setupMatcher`, `next` и `getGroup` сохраняют состояние между
ссылками на строку. Пока строки представлены `wstring`, некоторые разделяющие
буфер срезы могут ошибочно разделить состояние; незавершённый поиск сохраняется
в памяти до сброса или исчерпания. Именованные группы поддерживаются в проверенном
подмножестве синтаксиса.
`format` поддерживает подстановки `{n}`, кавычки и числовые форматы `number`,
`integer`, `percent`, `currency` и числовые шаблоны с префиксами, суффиксами,
процентами и форматом отрицательных значений по правилам русской локали, а также
базовые варианты `choice`. Форматы `date` и `time` принимают числовое значение
времени в миллисекундах, включая `datespan`; доступны стандартные стили русской
локали и поддерживаемые шаблоны даты. Другие форматы MessageFormat и аргументы
типов `date`/`binary` пока не реализованы.
Поддерживаются строковые преобразования `guid`, `datespan`, `date`, `geometry`,
`file` и `exception`, в том числе при конкатенации.
Строка также преобразуется в `exception` при присваивании и передаче в методы.
Для массивов поддерживаются инициализаторы `{...}`,
индексация, методы `size`, `isEmpty`, `get`, `set`, `add`, `addAll`, `contains`,
`indexOf`, `remove`, `removeAt`, `removeAll`, `reverse`, `sort`, `unique`,
`isSubsetOf`, `join`, `clear` и операторы `+` и `+=`. Массивы передаются по ссылке;
`first` и `last` доступны для всех этих массивов; результат пустого массива можно
сравнить с `null` или использовать с `?:`. Для `int` доступны также арифметика и
сравнения и сохранение результата в переменной или передача в метод; для `bool`
доступны логические операции, для `decimal` — арифметика и сравнения.
для массивов объектов поддерживаются литералы, индексация, `foreach`, `size`,
`isEmpty`, `clear`, `get`, `add`, `addAll`, `set`, `removeAt`, `contains`,
`indexOf`, `remove`, `removeAll`, `isSubsetOf`, `reverse`, `unique` и передача в методы.
Типы массивов объектов должны совпадать; элементы могут принадлежать классам-наследникам.
Для отображений поддерживаются `string[string]` и `primary[string]`: создание, передача по ссылке,
чтение и присваивание по ключу, `add` (значения или другого отображения), `get`,
`remove`, `keys`, `values`, `size`, `isEmpty`, `containsKey`, операторы `+` и `+=`,
`containsValue` и `clear`. Результат отсутствующего ключа можно сравнить с `null`
или использовать слева от `?:`, сохранять в переменную соответствующего типа,
передавать в метод и возвращать из метода. Ключи и значения также могут быть `null`.
Возвращаемые `add` и `remove` значения поддерживают те же проверки. Составные
присваивания элементу пока не поддерживаются. Присваивание по индексу не подтверждено сравнением исполнения:
оригинальный компилятор принимает его, но генерирует некомпилируемую Java.
`keys` и `values` возвращают снимки; порядок их элементов пока может отличаться
от порядка Java `HashMap`.
Другие виды отображений, многомерные массивы, остальные
методы коллекций и все особенности ссылочной семантики элементов пока не перенесены.
Для некоторых присваиваний элементам массива исходный компилятор принимает `.bl`,
но генерирует Java, которая не компилируется; поведение z8-d в таких случаях не
подтверждено сравнением выполнения с оригиналом.
Для `decimal` реализованы литералы, неявное преобразование из `int`, арифметика,
сравнения, `parse()`, `round()`, `floor()`, `ceil()`, `signum()`, `abs()`,
тригонометрические и гиперболические функции, логарифмы, степени и корни.
Эти математические функции доступны также для `int`.
Стандартный класс `org.zenframework.z8.lang.Math` поддерживает `PI`, перегрузки
`min` и `max` для чисел и дат, `hypot`, `sin`, `cos` и `random`.
Поддерживаются `int.Min`, `int.Max`, `decimal.Min`, `decimal.Max` и поля режимов
округления `decimal.Round*`; изменённый `RoundHalfUp` учитывается при `round(digits)`.
Для методов, использующих `double`, преобразование строки пока предполагает
десятичную точку в C-локали процесса. Вычисления используют целые произвольной точности и
сохраняют масштаб, включая ограничение точности и округление по правилам Z8.
Значение NaN поддерживается в арифметике, сравнении и математических функциях;
полная совместимость численных результатов с Java ещё не подтверждена.
Исходный компилятор пропускает десятичные литералы через Java `double`, в отличие
от `decimal.parse`, который читает строку точно. Для литералов z8-d пока принимает
не более 15 значащих цифр и ненулевые значения в диапазоне от `1e-15` до `1e15`
по модулю (верхняя граница исключена); для остальных значений используйте
`decimal.parse("...")`. Полная совместимость форматирования Java `double` ещё
не подтверждена.
Поддерживаются преобразования `int` → `decimal` и `int`/`bool`/`decimal` → `string`,
в том числе в явных приведениях и строковой конкатенации.
Для `int` доступны `parse`, `abs`, `signum`, побитовые методы и сдвиги,
`toString` с системой счисления, `toHexString` и `toBinaryString`; `parse` возвращает
`null` для пустой строки и принимает цифры Unicode по таблице Java 8. `decimal.parse`,
а также разбор дат и интервалов поддерживают эти цифры; в других версиях Java набор
может отличаться.
`bool.parse` поддерживает стандартные английские значения и настраиваемые значения
ресурсов: приложение может вызвать `z8_bool_set_resource_strings("да"w, "нет"w)`
при запуске. Автоматическая загрузка серверных ресурсов пока не реализована;
до настройки используются ключи `bool.true` и `bool.false`, как при отсутствии ресурсов Z8.
Смешанные сравнения `int` с `decimal` сохраняют особенности исходного runtime Z8.
Семантика ошибок и совместимость остальных крайних случаев пока не полностью совпадают с Z8.
Другие атрибуты, статические объектные поля, дополнительные стадии жизненного цикла и многие другие
конструкции не реализованы и не должны считаться поддерживаемыми. Для них
транслятор сообщает об ошибке.

`z8d project <каталог-исходников> <каталог-результата>` рекурсивно читает `.bl`-файлы
и записывает для каждого отдельный D-модуль в каталог результата. Повторный запуск
перезаписывает одноимённые сгенерированные файлы, но не удаляет устаревшие файлы:
перед полной повторной генерацией используйте пустой каталог. Имя класса должно совпадать с именем
файла; путь относительно каталога задаёт имя пакета. Поддерживаются `import`
по полному имени и доступ к классам из одного пакета. Между классами пока можно
вызывать публичные статические методы и использовать экземпляры видимых классов.
Проверяются наличие импортов,
конфликты имён, сигнатуры и доступность методов; диагностируется конкретный файл.
Имя D-класса при сборке проекта имеет вид `Z8p_` плюс шестнадцатеричное UTF-8
представление полного имени Z8: например, `demo.Main` → `Z8p_64656D6F2E4D61696E`.
Модули располагаются в `z8gen/`: например, `demo/Main.bl` становится
`z8gen/p_demo/p_Main.d`. Части имён кодируются, чтобы избежать конфликтов с ключевыми
словами D; нужные зависимости импортируются автоматически.
`project` выдаёт библиотечный код без точки входа. Команда
`z8d build <каталог> <полное-имя-класса.метод> <путь-к-программе>` добавляет точку
входа и вызывает DMD из `PATH`. Выбранный метод должен быть публичным статическим,
без аргументов и возвращать `void` или `int`; значение `int` становится кодом
завершения процесса с приведением к 32 битам. Имя выходного файла задаётся явно;
на Windows обычно используется расширение `.exe`.
Пример — [examples/project](examples/project).

Для команды `build` runtime по умолчанию собирается отдельно во временную
статическую библиотеку и связывается с результатом. Готовую библиотеку можно
использовать повторно, указав путь в `Z8_RUNTIME_LIB`. При запуске компилятора
вне каталога проекта задайте `Z8_RUNTIME_ROOT` — путь к каталогу `runtime`.
Исходники runtime при этом нужны D-компилятору для шаблонов и строковых импортов.

Например, в Windows можно один раз собрать библиотеку и использовать её так:

```powershell
New-Item -ItemType Directory -Force runtime/lib | Out-Null
dmd -lib -Iruntime/source -Jruntime/source runtime/source/z8/runtime.d runtime/source/z8/runtime_source.d -of=runtime/lib/z8-runtime.lib
$env:Z8_RUNTIME_LIB = (Resolve-Path runtime/lib/z8-runtime.lib).Path
./z8d.exe build examples/project demo.Main.run example-app.exe
```

При самостоятельной сборке сгенерированных модулей передайте DMD каталог
генерации через `-I`, `runtime/source` через `-I` и `-J`, все необходимые `.d`
файлы и статическую библиотеку runtime. Для отдельного `.bl` результат можно
сохранить перенаправлением stdout: `z8d compile examples/math.bl > math.d`.
В Windows PowerShell 5 для сохранения без преобразования кодировки используйте
`cmd /c "z8d.exe compile examples\math.bl > math.d"`.

## Структура исходного Z8 и дальнейший перенос

Исходный проект версии 1.3.0 содержит 12 Gradle-модулей:

- `compiler` — лексер, Yacc-грамматика, семантический анализ, генерация Java,
  управление проектами и документацией;
- `lang` — стандартная библиотека на `.bl`, использующая native-типы сервера;
- `server` — runtime, модели, SQL, хранилища, безопасность и сервисы;
- `boot`, `servlet`, `webserver`, `auth`, `interconnection`, `justintime`,
  `oda.driver` — запуск, транспорт и интеграции;
- `js`, `resources` — веб-клиент и ресурсы.

Следующие необходимые этапы: расширение грамматики и AST; полное разрешение типов и
семантический анализ; генерация D-кода и runtime всех встроенных типов; затем SQL,
серверные сервисы, интеграции и совместимость веб-клиента. Для подтверждения
эквивалентности потребуется сравнение с оригинальным компилятором и запуск
приложений Z8, а не только успешный лексический анализ.
