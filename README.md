# z8-d

Начало переноса платформы ZENFRAMEWORK Z8 на D. Реализованы лексический анализ
языка Z8 (`.bl`) и экспериментальная трансляция ограниченного подмножества языка
в D. Это **не полная реализация Z8**: стандартная библиотека, полноценный runtime,
сервер и веб-клиент пока отсутствуют.

## Сборка и запуск

Требуются DMD и DUB. Внешние пакеты D не используются.

```sh
dub build
dub test
dub run -- lex path/to/file.bl
dub run -- compile examples/math.bl
dub run -- project examples/project
dub run -- build examples/project demo.Main.run example-app
python tests/integration.py
python tests/decimal_oracle.py
python tests/string_oracle.py
python tests/lexer_oracle.py path/to/original-z8 --corpus
python tests/z8_compiler_oracle.py path/to/original-z8
```

Интеграционные проверки требуют Python 3 и DMD в `PATH`; двум проверкам с суффиксом
`oracle` также нужен JDK с `java` и `javac`. Они компилируют сгенерированный D-код
и сравнивают результаты с Java `BigDecimal` и строками UTF-16.
Две последние проверки дополнительно используют исходники оригинального Z8;
для проверки компилятора нужны также его кэшированные Eclipse-зависимости. Если
задать переменную `Z8_ORACLE_RUN=1`, пример проекта дополнительно выполняется и
сравнивается с D-версией, используя имеющиеся собранные классы и JAR оригинального
runtime. Этот JAR может отличаться по версии от текущих исходников.

`z8d lex` выводит по одному JSON-объекту на токен. `kind` — категория,
`text` — исходное написание, `offset` и `length` измеряются в кодовых единицах
UTF-16, `line` и `column` отсчитываются с нуля. Пробелы и комментарии пропускаются.
Ошибка лексического анализа выводится в stderr с позицией, код выхода — 1;
неверные аргументы дают код 2. Файл должен быть в UTF-8.

Поддерживаются ключевые и зарезервированные слова исходного компилятора,
операторы, вложенные блочные и однострочные комментарии, строки с escape-последовательностями,
числа, даты, интервалы, GUID и бинарные литералы. Семантические значения литералов
пока не вычисляются: наружу возвращается исходный текст. Unicode-идентификаторы
проверяются по категориям букв и чисел D, поэтому возможны отличия от Java
`Character.isJavaIdentifierPart`. Совместимость не подтверждена для всех краевых
случаев оригинального лексера.

### Трансляция в D

`z8d compile file.bl` разбирает исходный текст, проверяет типы и выводит D-код
в stdout. Результат представляет собой библиотечный код, а не готовую исполняемую
программу. Ошибки выводятся в stderr с позицией; при ошибке код не выводится.

Поддерживается один класс или перечисление на файл. Для перечислений реализованы
именованные значения, сравнение, `null`, поля с явным инициализатором, параметры,
возвращаемые значения и `?:`. Атрибут `[native "..."]` в объявлении перечисления
распознаётся, но связь с внешним Java-типом не создаётся. Для одномерных массивов
перечислений поддерживаются те же основные операции, что для массивов объектов.
Статические поля перечислений и переменные перечислений без явного инициализатора
пока не поддерживаются; для последнего случая оригинальный компилятор генерирует
некомпилируемую Java.

Классы поддерживаются с реализованными статическими
и экземплярными методами. Методы можно перегружать, в том числе добавляя
экземплярные перегрузки в наследнике; смешивание статических и экземплярных
перегрузок одного имени и перегрузки унаследованных статических методов пока не поддерживаются.
Внутри класса доступны поля базовых
и объектных типов, `this`, `new ИмяКласса` и локальные переменные объектного типа.
Статические поля поддерживаются для базовых типов и их одномерных массивов;
инициализатор статического поля пока должен быть константным выражением.
Оригинальный компилятор запрещает статические поля пользовательских классов.
Видимые классы можно использовать в параметрах и возвращаемых значениях, а также
обращаться к их публичным полям и методам. Циклическое автоматическое создание
объектных полей отклоняется, чтобы избежать бесконечной рекурсии.
Поддерживается одиночное наследование через `extends`, публичные и защищённые
унаследованные члены, `super` и переопределение виртуальных методов с совпадающими
сигнатурами. Полное поведение объектов и сложные сценарии наследования ещё не перенесены.
Поддерживаются явные приведения между базовым и производным классами с проверкой
типа во время выполнения; другие объектные приведения пока не реализованы.
Для таких классов также поддерживается проверка типа `instanceof`.
Поддерживается базовый `void constructor()` без параметров: он вызывается после
инициализации полей, включая поля предков. Переопределённый конструктор может
явно вызвать `super.constructor()`; остальные стадии жизненного цикла Z8 не перенесены.
Типы: `int` (64-битный знаковый), `decimal`, `bool`,
`string`, `exception`, одномерные массивы `int`, `decimal`, `bool`, `string`
и пользовательских классов,
а также `void` (для возвращаемого значения).
В телах поддерживаются блоки,
локальные переменные, присваивания и составные присваивания, `return`, `if`/`else`,
`while`, `do`/`while`, обычный `for`, `break`, `continue`, вызовы методов того же
класса, целочисленные, логические и строковые литералы, тернарный оператор и часть
других операторов. Обычный `for` требует условия и выражения шага, как в грамматике
Z8; также поддерживается `for (тип элемент : массив)` для одномерных массивов.
Поддерживаются `throw` с `exception` или `string`, `try` с одним
`catch (exception ...)` и/или `finally`, а также `exception.getMessage()`.
`null` поддерживается для переменных, аргументов и возвращаемых значений объектных
типов, массивов и `string[string]`, включая сравнение с `null`. Для них также
поддерживается оператор `?:` с ленивым вычислением правой части.
Обращение к пустой ссылке вызывает исключение. `null` для примитивных типов и прямой инициализатор
`null` у объектного поля пока не поддерживаются; в оригинале такой инициализатор
поля вызывает ошибку при создании объекта.
Переходы `return`, `break` и `continue` внутри `finally` пока не поддержаны.
Объявления без инициализатора получают значения `0`, `false`, пустую строку или
пустой массив; `exception` создаётся с пустым сообщением.
Проверяются имена, типы аргументов и выражений, области видимости и наличие
возвращаемого значения на всех путях. Затенение переменных запрещено.

Имя класса `Math` в D становится `Z8_Math`, а метод `add` — `m_add`; пример входа
находится в [examples/math.bl](examples/math.bl). `&&` и `||` сохраняют короткое
замыкание; деление и остаток учитывают крайний случай `long.min / -1`. Строки в D
представлены `wstring` (UTF-16), включая сравнение по кодовым единицам Java.
Поддерживаются конкатенация, сравнения, `length`, `isEmpty`, `compare`, `startsWith`,
`endsWith`, `indexOf`, `lastIndexOf`, `substring`, `charAt`, `trim`, `trimLeft`,
`trimRight`, `left`, `right`, `insert`, `replace`, `padLeft` и `padRight`; остальные методы строк
ещё не перенесены. Для массивов поддерживаются инициализаторы `{...}`,
индексация, методы `size`, `isEmpty`, `get`, `set`, `add`, `addAll`, `contains`,
`indexOf`, `remove`, `removeAt`, `removeAll`, `reverse`, `sort`, `unique`,
`isSubsetOf`, `join`, `clear` и операторы `+` и `+=`. Массивы передаются по ссылке;
для массивов объектов поддерживаются литералы, индексация, `foreach`, `size`,
`isEmpty`, `clear`, `get`, `add`, `addAll`, `set`, `removeAt`, `contains`,
`indexOf`, `remove`, `removeAll`, `isSubsetOf`, `reverse`, `unique` и передача в методы.
Типы массивов объектов должны совпадать; элементы могут принадлежать классам-наследникам.
Для отображений поддерживается только `string[string]`: создание, передача по ссылке,
чтение и присваивание по ключу, `add` (значения или другого отображения), `get`,
`remove`, `keys`, `values`, `size`, `isEmpty`, `containsKey`, операторы `+` и `+=`,
`containsValue` и `clear`. Результат отсутствующего ключа можно сравнить с `null`
или использовать слева от `?:`. При присваивании такого результата строковой
переменной пока возникает исключение: полноценная семантика `null` для строк
ещё не перенесена.
Возвращаемые `add` и `remove` значения поддерживают те же проверки. Составные
присваивания элементу пока не поддерживаются. Присваивание по индексу не подтверждено сравнением исполнения:
оригинальный компилятор принимает его, но генерирует некомпилируемую Java.
`keys` и `values` возвращают снимки; порядок их элементов пока может отличаться
от порядка Java `HashMap`.
Другие виды отображений, многомерные массивы, остальные
методы коллекций и все особенности ссылочной семантики элементов пока не перенесены.
Для некоторых присваиваний элементам массива исходный компилятор принимает `.bl`,
но генерирует Java, которая не компилируется; поведение z8-d в таких случаях не
подтверждено сравнением выполнения с оригиналом.
Для `decimal` реализованы литералы, неявное преобразование из `int`, арифметика,
сравнения, `parse()`, `round()`, `floor()`, `ceil()`, `signum()` и `toString()`.
Для методов, использующих `double`, преобразование строки пока предполагает
десятичную точку в C-локали процесса. Вычисления используют целые произвольной точности и
сохраняют масштаб, включая ограничение точности и округление по правилам Z8;
специальное значение NaN и остальные методы `decimal` пока не реализованы.
Исходный компилятор пропускает десятичные литералы через Java `double`, в отличие
от `decimal.parse`, который читает строку точно. Для литералов z8-d пока принимает
не более 15 значащих цифр и ненулевые значения в диапазоне от `1e-15` до `1e15`
по модулю (верхняя граница исключена); для остальных значений используйте
`decimal.parse("...")`. Полная совместимость форматирования Java `double` ещё
не подтверждена.
Поддерживаются преобразования `int` → `decimal` и `int`/`bool`/`decimal` → `string`,
в том числе в явных приведениях и строковой конкатенации.
Для `int` доступны `parse`, `abs`, `signum`, побитовые методы и сдвиги,
`toString` с системой счисления, `toHexString` и `toBinaryString`; `parse` пока принимает
только ASCII-цифры и сообщает об ошибке на пустой строке, вместо возвращения `null`.
`bool.parse` поддерживает стандартные английские значения; локализованные значения
из ресурсов сервера пока не загружаются.
Смешанные сравнения `int` с `decimal` сохраняют особенности исходного runtime Z8.
Семантика ошибок и совместимость остальных крайних случаев пока не полностью совпадают с Z8.
Другие атрибуты, статические объектные поля, дополнительные стадии жизненного цикла и многие другие
конструкции не реализованы и не должны считаться поддерживаемыми. Для них
транслятор сообщает об ошибке.

`z8d project <каталог>` рекурсивно читает `.bl`-файлы из одного каталога
исходников и выводит общий D-код в stdout. Имя класса должно совпадать с именем
файла; путь относительно каталога задаёт имя пакета. Поддерживаются `import`
по полному имени и доступ к классам из одного пакета. Между классами пока можно
вызывать публичные статические методы и использовать экземпляры видимых классов.
Проверяются наличие импортов,
конфликты имён, сигнатуры и доступность методов; диагностируется конкретный файл.
Имя D-класса при сборке проекта имеет вид `Z8p_` плюс шестнадцатеричное UTF-8
представление полного имени Z8: например, `demo.Main` → `Z8p_64656D6F2E4D61696E`.
`project` выдаёт библиотечный код без точки входа. Команда
`z8d build <каталог> <полное-имя-класса.метод> <путь-к-программе>` добавляет точку
входа и вызывает DMD из `PATH`. Выбранный метод должен быть публичным статическим,
без аргументов и возвращать `void` или `int`; значение `int` становится кодом
завершения процесса с приведением к 32 битам. Имя выходного файла задаётся явно;
на Windows обычно используется расширение `.exe`.
Пример — [examples/project](examples/project).

## Структура исходного Z8 и дальнейший перенос

Исходный проект версии 1.3.0 содержит 12 Gradle-модулей:

- `compiler` — лексер, Yacc-грамматика, семантический анализ, генерация Java,
  управление проектами и документацией;
- `lang` — стандартная библиотека на `.bl`, использующая native-типы сервера;
- `server` — runtime, модели, SQL, хранилища, безопасность и сервисы;
- `boot`, `servlet`, `webserver`, `auth`, `interconnection`, `justintime`,
  `oda.driver` — запуск, транспорт и интеграции;
- `js`, `resources` — веб-клиент и ресурсы.

Следующие необходимые этапы: расширение грамматики и AST; полное разрешение типов и
семантический анализ; генерация D-кода и runtime всех встроенных типов; затем SQL,
серверные сервисы, интеграции и совместимость веб-клиента. Для подтверждения
эквивалентности потребуется сравнение с оригинальным компилятором и запуск
приложений Z8, а не только успешный лексический анализ.
