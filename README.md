# z8-d

Начало переноса платформы ZENFRAMEWORK Z8 на D. Реализованы лексический анализ
языка Z8 (`.bl`) и экспериментальная трансляция ограниченного подмножества языка
в D. Это **не полная реализация Z8**: стандартная библиотека, полноценный runtime,
сервер и веб-клиент пока отсутствуют.

## Сборка и запуск

Требуются DMD и DUB. Внешние пакеты D не используются.

```sh
dub build
dub test
dub run -- lex path/to/file.bl
dub run -- compile examples/math.bl
dub run -- project examples/project
dub run -- build examples/project demo.Main.run example-app
python tests/integration.py
```

Последняя команда дополнительно требует Python 3 и DMD в `PATH`; она компилирует
сгенерированный D-код и проверяет результат его выполнения.

`z8d lex` выводит по одному JSON-объекту на токен. `kind` — категория,
`text` — исходное написание, `offset` и `length` измеряются в кодовых единицах
UTF-16, `line` и `column` отсчитываются с нуля. Пробелы и комментарии пропускаются.
Ошибка лексического анализа выводится в stderr с позицией, код выхода — 1;
неверные аргументы дают код 2. Файл должен быть в UTF-8.

Поддерживаются ключевые и зарезервированные слова исходного компилятора,
операторы, вложенные блочные и однострочные комментарии, строки с escape-последовательностями,
числа, даты, интервалы, GUID и бинарные литералы. Семантические значения литералов
пока не вычисляются: наружу возвращается исходный текст. Unicode-идентификаторы
проверяются по категориям букв и чисел D, поэтому возможны отличия от Java
`Character.isJavaIdentifierPart`. Совместимость не подтверждена для всех краевых
случаев оригинального лексера.

### Трансляция в D

`z8d compile file.bl` разбирает исходный текст, проверяет типы и выводит D-код
в stdout. Результат представляет собой библиотечный код, а не готовую исполняемую
программу. Ошибки выводятся в stderr с позицией; при ошибке код не выводится.

Поддерживается один класс на файл без наследования, с реализованными статическими
и экземплярными методами, без перегрузки. Внутри класса доступны поля базовых
типов, `this`, `new ИмяКласса` и локальные переменные типа текущего класса.
Типы: `int` (64-битный знаковый), `bool`,
`string`, `exception`, одномерные массивы первых трёх типов и `void` (для возвращаемого значения).
В телах поддерживаются блоки,
локальные переменные, присваивания и составные присваивания, `return`, `if`/`else`,
`while`, `do`/`while`, обычный `for`, `break`, `continue`, вызовы методов того же
класса, целочисленные, логические и строковые литералы, тернарный оператор и часть
других операторов. Обычный `for` требует условия и выражения шага, как в грамматике
Z8; также поддерживается `for (тип элемент : массив)` для одномерных массивов.
Поддерживаются `throw` с `exception` или `string`, `try` с одним
`catch (exception ...)` и/или `finally`, а также `exception.getMessage()`.
Переходы `return`, `break` и `continue` внутри `finally` пока не поддержаны.
Объявления без инициализатора получают значения `0`, `false`, пустую строку или
пустой массив; `exception` создаётся с пустым сообщением.
Проверяются имена, типы аргументов и выражений, области видимости и наличие
возвращаемого значения на всех путях. Затенение переменных запрещено.

Имя класса `Math` в D становится `Z8_Math`, а метод `add` — `m_add`; пример входа
находится в [examples/math.bl](examples/math.bl). `&&` и `||` сохраняют короткое
замыкание; деление и остаток учитывают крайний случай `long.min / -1`. Строки в D
представлены `wstring` (UTF-16), включая сравнение по кодовым единицам Java.
Поддерживаются конкатенация, сравнения и методы `length()` и `isEmpty()`; остальные
методы строк ещё не перенесены. Для массивов поддерживаются инициализаторы `{...}`,
индексация, методы `size`, `isEmpty`, `get`, `set`, `add` с одним аргументом и
`clear`. Массивы передаются по ссылке; отображения, многомерные массивы, остальные
методы коллекций и все особенности ссылочной семантики элементов пока не перенесены.
Семантика ошибок и совместимость остальных крайних случаев пока не полностью совпадают с Z8.
Атрибуты, статические поля, наследование, Z8-конструкторы, объектные поля,
типы других классов в сигнатурах, перегрузки, `decimal` и многие другие
конструкции не реализованы и не должны считаться поддерживаемыми. Для них
транслятор сообщает об ошибке.

`z8d project <каталог>` рекурсивно читает `.bl`-файлы из одного каталога
исходников и выводит общий D-код в stdout. Имя класса должно совпадать с именем
файла; путь относительно каталога задаёт имя пакета. Поддерживаются `import`
по полному имени и доступ к классам из одного пакета. Между классами пока можно
вызывать только публичные статические методы без объектных типов в сигнатуре.
Проверяются наличие импортов,
конфликты имён, сигнатуры и доступность методов; диагностируется конкретный файл.
Имя D-класса при сборке проекта имеет вид `Z8p_` плюс шестнадцатеричное UTF-8
представление полного имени Z8: например, `demo.Main` → `Z8p_64656D6F2E4D61696E`.
`project` выдаёт библиотечный код без точки входа. Команда
`z8d build <каталог> <полное-имя-класса.метод> <путь-к-программе>` добавляет точку
входа и вызывает DMD из `PATH`. Выбранный метод должен быть публичным статическим,
без аргументов и возвращать `void` или `int`; значение `int` становится кодом
завершения процесса с приведением к 32 битам. Имя выходного файла задаётся явно;
на Windows обычно используется расширение `.exe`.
Пример — [examples/project](examples/project).

## Структура исходного Z8 и дальнейший перенос

Исходный проект версии 1.3.0 содержит 12 Gradle-модулей:

- `compiler` — лексер, Yacc-грамматика, семантический анализ, генерация Java,
  управление проектами и документацией;
- `lang` — стандартная библиотека на `.bl`, использующая native-типы сервера;
- `server` — runtime, модели, SQL, хранилища, безопасность и сервисы;
- `boot`, `servlet`, `webserver`, `auth`, `interconnection`, `justintime`,
  `oda.driver` — запуск, транспорт и интеграции;
- `js`, `resources` — веб-клиент и ресурсы.

Следующие необходимые этапы: расширение грамматики и AST; полное разрешение типов и
семантический анализ; генерация D-кода и runtime всех встроенных типов; затем SQL,
серверные сервисы, интеграции и совместимость веб-клиента. Для подтверждения
эквивалентности потребуется сравнение с оригинальным компилятором и запуск
приложений Z8, а не только успешный лексический анализ.
